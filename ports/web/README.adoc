= quiet CSS / Web reference port

The quiet web reference port exposes quiet-core semantic colors as CSS
custom properties.

It does not define application layout, typography, widgets, or component
styling.

quiet ports color systems.  It does not skin applications.

== Artifact

The generated stylesheet is:

----
ports/web/quiet.css
----

It is generated from the canonical quiet-day and quiet-night palette data.

The stylesheet MUST NOT be edited independently of the generator.

== Variables

The web port exposes the ten canonical quiet anchors:

----
--quiet-field
--quiet-surface
--quiet-structure
--quiet-ink
--quiet-muted
--quiet-line
--quiet-mineral
--quiet-moss
--quiet-ochre
--quiet-rust
----

It also exposes the opaque derived roles:

----
--quiet-selection
--quiet-callout
--quiet-mineral-wash
--quiet-mineral-wash-emphasis
--quiet-moss-wash
--quiet-moss-wash-emphasis
--quiet-ochre-wash
--quiet-ochre-wash-emphasis
--quiet-rust-wash
--quiet-rust-wash-emphasis
----

The wash variables are the canonical washes over Field.  A wash placed on
another background is a different color and should be derived with the
reference implementation.

These names preserve quiet-core semantics directly.

The web port does not create aliases such as `--quiet-background`,
`--quiet-success`, or `--quiet-error`.

Applications MAY define their own aliases from quiet roles.

== Day and Night

Without an explicit override, quiet-day is the default adaptation.

When the root document has no `data-quiet-theme` attribute, the stylesheet
uses `prefers-color-scheme: dark` to select quiet-night for users requesting
a dark interface.

An explicit theme may be selected with:

----
<html data-quiet-theme="day">
----

or:

----
<html data-quiet-theme="night">
----

Explicit selection takes precedence over the system preference.

== Subtle

quiet Subtle is contextual.

There is deliberately no:

----
--quiet-subtle
----

global CSS variable.

Subtle is Muted composited at 55 percent over the actual local background.

For a known Field background, a web implementation may express the rule as:

----
color: color-mix(
    in srgb,
    var(--quiet-muted) 55%,
    var(--quiet-field) 45%
);
----

A Surface context must use Surface instead:

----
color: color-mix(
    in srgb,
    var(--quiet-muted) 55%,
    var(--quiet-surface) 45%
);
----

A port MUST NOT treat either result as a universal opaque Subtle color.

== Example

A minimal document surface may use:

----
body {
    background: var(--quiet-field);
    color: var(--quiet-ink);
}

aside {
    background: var(--quiet-surface);
    color: var(--quiet-muted);
}

::selection {
    background: var(--quiet-selection);
    color: var(--quiet-ink);
}

a {
    color: var(--quiet-mineral);
}
----

These mappings illustrate semantic use.

They are not a complete quiet application skin.

== Generation

Regenerate the canonical stylesheet with:

----
make web
----

The repository test suite verifies that the committed stylesheet is exactly
the output produced from the canonical quiet palettes.
