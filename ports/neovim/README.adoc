= quiet for Neovim

quiet-day and quiet-night for Neovim.

The port maps quiet-core semantics directly onto Neovim UI, syntax,
Tree-sitter, diagnostic, and LSP semantic-token highlight groups.

It introduces no independent color policy.

== Architecture

----
quiet-core
    |
    v
Neovim semantic mapping
    |
    v
native Lua colorscheme
----

== Syntax

quiet deliberately avoids rainbow syntax.

Ordinary source remains Ink.

Comments and secondary information use Muted.

Language structure such as keywords, types, directives, and operators uses
Mineral.

Moss, Ochre, and Rust are reserved for semantic state such as success,
warnings, errors, and diff state.

== Diff, search, and references

[cols="2,2"]
|===
| Neovim group | quiet role

| `DiffAdd` / `DiffChange`
| Moss wash / Ochre wash, keeping syntax colors

| `DiffDelete`
| Rust on Rust wash

| `DiffText`
| Ink on Ochre wash emphasis

| `Added` / `Changed` / `Removed`
| Moss / Ochre / Rust text, for diff and patch files

| `Search`
| Mineral wash, keeping syntax colors

| `CurSearch`, `IncSearch`
| Ink on Selection

| `LspReferenceText`, `LspReferenceRead` / `LspReferenceWrite`
| Mineral wash / Ochre wash
|===

Line washes keep every syntax color at its contract minimum, so these
groups set no foreground.  The emphasis tier guarantees only Ink, so
`DiffText` sets Ink, as the delta port does.

== Diagnostics and spelling

Diagnostics use Rust, Ochre, and Mineral, with Moss for `DiagnosticOk`.

Neovim underlines diagnostics, strikes through deprecated names, and
undercurls misspellings.  quiet keeps those cues and colors them: the code
beneath keeps its syntax colors.  `SpellBad`, `SpellCap`, `SpellLocal`, and
`SpellRare` take Rust, Ochre, Moss, and Mineral.

== Terminal

The port sets `g:terminal_color_0` through `g:terminal_color_15` from
quiet's generic terminal palette, so `:terminal` matches quiet's other
terminal ports.

== Installation

The schemes install from the quiet repository.  `ports/neovim` is a
runtime directory: add it to `runtimepath`, then choose a scheme.

With lazy.nvim:

----
{
  "chrismecca/quiet",
  lazy = false,
  priority = 1000,
  config = function(plugin)
    vim.opt.runtimepath:append(plugin.dir .. "/ports/neovim")
    vim.cmd.colorscheme("quiet-night")
  end,
}
----

With Neovim's built-in `vim.pack` (Neovim 0.12 or later):

----
vim.pack.add({ "https://github.com/chrismecca/quiet" })
vim.opt.runtimepath:append(
  vim.fn.stdpath("data") .. "/site/pack/core/opt/quiet/ports/neovim"
)
vim.cmd.colorscheme("quiet-night")
----

Or copy the files into Neovim's colors directory:

----
mkdir -p ~/.config/nvim/colors
cp ports/neovim/colors/*.lua ~/.config/nvim/colors/
----

Then select a scheme with `:colorscheme quiet-day` or
`:colorscheme quiet-night`.

== Name

Neovim ships an unrelated colorscheme named `quiet`, a mostly monochrome
scheme from the Vim colorschemes project.  `:colorscheme quiet` selects
that scheme, not this port.

quiet's schemes are always named `quiet-day` and `quiet-night`, so they
never replace Neovim's `quiet` and Neovim's never replaces them.

== Clean validation

`--clean` intentionally omits the normal user runtime path.

To validate an installed quiet scheme with an otherwise clean Neovim:

----
nvim --clean \
  --cmd "set runtimepath^=$HOME/.config/nvim" \
  +'colorscheme quiet-day'
----

and:

----
nvim --clean \
  --cmd "set runtimepath^=$HOME/.config/nvim" \
  +'colorscheme quiet-night'
----

The schemes in this repository can also be validated directly:

----
nvim --clean --headless \
  +'set runtimepath^=ports/neovim' \
  +'colorscheme quiet-day' \
  +'lua assert(vim.g.colors_name == "quiet-day")' \
  +qa
----

== Scope

The first-party port controls color only.

It keeps the cues that mark state in Neovim's own defaults: underlines,
undercurls, and strikethroughs on diagnostics, spelling, and links.  It
drops Neovim's typographic emphasis, such as bold keywords, and does not
impose:

* font family;
* font weight;
* italics;
* cursor shape;
* layout;
* plugin configuration.

quiet ports color systems.

It does not skin applications.

== Generation

----
make neovim
----

The repository tests verify that the committed artifacts match the reference
implementation, and that every group with a background keeps its text at
its contract minimum.

Where Neovim is installed, the tests also load both schemes in a clean
Neovim and check that each group keeps exactly the state cues Neovim's own
default gives it.  Set `QUIET_NVIM` to choose a binary.
