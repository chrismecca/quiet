= quiet for CDE

quiet's CDE port maps quiet semantic architecture onto the Common Desktop
Environment high-color palette model.

The reference port was developed and visually validated on a real CDE desktop.

== Files

----
quiet-day.dp
quiet-night.dp
----

These files are generated from the canonical quiet palettes.

== Installation

Copy the generated palettes into the user's CDE palette directory:

----
mkdir -p "$HOME/.dt/palettes"

cp quiet-day.dp \
    quiet-night.dp \
    "$HOME/.dt/palettes/"
----

Open:

----
Style Manager
    Color
----

and select either `quiet-day` or `quiet-night`.

== CDE color sets

A CDE high-color palette contains eight base color sets.

CDE uses those bases to derive additional Motif colors including foreground,
top-shadow, bottom-shadow, and selection colors.

quiet therefore maps architectural roles to CDE base sets rather than trying
to replace CDE's derived colors individually.

[cols="1,3,2"]
|===
| Set | CDE role | quiet role

| 1
| Active window frame
| Selection

| 2
| Inactive window frame
| Structure

| 3
| Workspace 1
| Field

| 4
| Text and list entry areas
| Field

| 5
| Main application background
| Surface

| 6
| Menus, dialogs, and dtterm background
| Surface

| 7
| Workspace 4
| Field

| 8
| Front Panel
| Structure
|===

Repeated quiet roles are intentional.

CDE requires eight color-set positions. quiet does not require eight visually
distinct architectural colors.

== Contextual adaptation

Direct use of the canonical architectural colors was tested on the reference
CDE system.

quiet-night placed the CDE base colors too near the low end of the available
lightness range. CDE's derived shadows and bevels consequently compressed into
a very dark visual mass.

quiet-day placed the base colors too near the high end. CDE's derived
highlights consequently lost useful headroom.

The reference port therefore applies a CDE-local OKLab lightness adaptation
before serialization:

----
quiet-day:

    L = L - 0.08
    a = unchanged
    b = unchanged

quiet-night:

    L = L + 0.10
    a = unchanged
    b = unchanged
----

This is a contextual port derivation.

It does not modify quiet-core or create new canonical anchors.

Derived colors must remain inside the sRGB gamut.

== Native representation

CDE `.dp` palettes use sixteen-bit X color components.

The reference quiet serializer exports the validated eight-bit sRGB value into
the high byte of each component:

----
#RRGGBB

becomes

#RR00GG00BB00
----

For example:

----
#BAC3C7

becomes

#BA00C300C700
----

Quantization occurs only at export.

== Host limitation

CDE color set 6 is shared by several host roles, including menus, dialogs,
workspace color, and dtterm background.

Those roles do not correspond to one exact quiet semantic role.

The reference port maps color set 6 to Surface because Surface is the closest
shared architectural interpretation.

quiet does not add application-specific overrides to compensate for this CDE
constraint.

== Semantic boundary

quiet does not force every canonical anchor into every host.

The CDE palette model primarily describes desktop architecture.

Moss, Ochre, and Rust are therefore not inserted into CDE color sets merely
to make them visible.

CDE remains responsible for its own widget rendering, shadows, bevels,
foreground generation, window-management behavior, and interaction model.

quiet ports color systems.

It does not redesign CDE.
