= quiet for Vim

The quiet Vim port maps quiet-core semantics onto Vim's native highlight
groups.

It is designed for both GUI-capable Vim and terminal Vim with truecolor
support.

== Artifacts

----
ports/vim/colors/quiet-day.vim
ports/vim/colors/quiet-night.vim
----

The files are generated artifacts.

They MUST NOT be edited independently of the reference implementation.

== Design

quiet does not treat programming-language token classes as unrelated semantic
state colors merely to maximize syntax differentiation.

Strings are not success.

Numbers are not warnings.

Regular expressions are not errors.

The Vim port therefore uses a restrained syntax hierarchy:

----
Ink       ordinary source content
Muted     comments and secondary text
Mineral   language structure and active syntax
----

quiet's semantic chromatic families are reserved for roles that actually
carry corresponding meaning.

For example:

----
Moss      diff additions
Ochre     warnings and attention
Rust      errors and diff deletions
Mineral   active navigation and focus
----

== Syntax hierarchy

The principal syntax mappings are:

[cols="2,1"]
|===
| Vim group | quiet role

| `Normal`
| Ink on Field

| `Comment`
| Muted

| `Constant`
| Ink

| `Identifier`
| Ink

| `Statement`
| Mineral

| `PreProc`
| Mineral

| `Type`
| Mineral

| `Special`
| Ink

| `Underlined`
| Mineral

| `Ignore`
| Subtle
|===

Standard Vim syntax subgroups link into those broader roles.

Examples include:

----
Character   -> Constant
Number      -> Constant
Boolean     -> Constant
Float       -> Constant

Function    -> Identifier

Conditional -> Statement
Repeat      -> Statement
Operator    -> Statement
Keyword     -> Statement

Include     -> PreProc
Define      -> PreProc
Macro       -> PreProc

StorageClass -> Type
Structure    -> Type
Typedef      -> Type
----

The purpose is hierarchy rather than token-by-token color proliferation.

== Diff semantics

Diff state is one of the places where quiet's chromatic semantic families
apply directly.

[cols="2,1"]
|===
| Vim group | quiet role

| `DiffAdd`
| Moss wash, keeping syntax colors

| `DiffChange`
| Ochre wash, keeping syntax colors

| `DiffDelete`
| Rust on Rust wash

| `DiffText`
| Ink on Ochre wash emphasis

| `Added`
| Moss

| `Changed`
| Ochre

| `Removed`
| Rust
|===

Line washes keep every syntax color at its contract minimum, so `DiffAdd`,
`DiffChange`, and `Search` set no foreground.  The emphasis tier guarantees
only Ink, so `DiffText` sets Ink, as the delta port does.

Washes need truecolor.  In a 16-color terminal, `DiffAdd`, `DiffChange`,
and `DiffDelete` color their text Moss, Ochre, and Rust instead, and
`Search` keeps Ink on Selection.

== Terminal integration

The Vim port embeds the same sixteen-color ANSI palette produced by quiet's
generic terminal reference port.

This is exposed through:

----
g:terminal_ansi_colors
----

The ANSI values therefore remain consistent with other first-party terminal
ports.

The Vim colorscheme does not maintain a separate terminal palette.

== Truecolor

When Vim runs in a terminal with truecolor support, enable:

----
set termguicolors
----

Vim will then use the exact `guifg` and `guibg` values emitted by the quiet
port.

Without truecolor, the generated `ctermfg` and `ctermbg` mappings fall back to
quiet's generic ANSI slots.

== Typography

quiet does not define Vim typography policy.

The generated colorschemes deliberately avoid forcing:

* bold;
* italic;
* underline;
* undercurl;
* font selection;
* font size.

Those are separate host and user preferences.

quiet ports color systems.

It does not skin applications.

== Installation

The schemes install from the quiet repository.  `ports/vim` is a runtime
directory: add it to `runtimepath`, then choose a scheme.

With vim-plug:

----
Plug 'chrismecca/quiet', { 'rtp': 'ports/vim' }
----

With Vim's own packages, clone the repository and add the runtime
directory in your vimrc:

----
git clone https://github.com/chrismecca/quiet ~/.vim/pack/quiet/opt/quiet
----

----
set runtimepath+=~/.vim/pack/quiet/opt/quiet/ports/vim
----

Or copy the files into Vim's colors directory:

----
mkdir -p ~/.vim/colors
cp ports/vim/colors/*.vim ~/.vim/colors/
----

Then select one from Vim:

----
:colorscheme quiet-day
----

or:

----
:colorscheme quiet-night
----

For truecolor terminal Vim:

----
:set termguicolors
----

== Name

Vim 9 ships an unrelated colorscheme named `quiet`, a mostly monochrome
scheme from the Vim colorschemes project.  `:colorscheme quiet` selects
that scheme, not this port.

quiet's schemes are always named `quiet-day` and `quiet-night`, so they
never replace Vim's `quiet` and Vim's never replaces them.

== Reference capture

For a clean reference session without depending on the user's normal Vim
configuration:

----
vim -Nu NONE \
    +'filetype on' \
    +'syntax enable' \
    +'set termguicolors' \
    +'colorscheme quiet-day' \
    QuietThemeProbe.swift
----

quiet-night:

----
vim -Nu NONE \
    +'filetype on' \
    +'syntax enable' \
    +'set termguicolors' \
    +'colorscheme quiet-night' \
    QuietThemeProbe.swift
----

This is useful for testing the Vim mapping independently of plugins or local
configuration.

== Scope

The Vim port controls colors only.

It does not:

* install plugins;
* change key mappings;
* alter indentation;
* modify statusline plugins;
* configure completion frameworks;
* change fonts;
* change terminal settings;
* redefine application layout.

Plugin-specific highlight groups may require separate mappings when a plugin
introduces semantics not covered by Vim's standard groups.

Such mappings should follow `PORTING.adoc`.

== Generation

Regenerate both canonical schemes with:

----
make vim
----

The repository tests verify that committed artifacts exactly match the
reference generator.
