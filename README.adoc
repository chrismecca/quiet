= Quiet.

A restrained color system for long-duration work.

_The interface should become scenery._

Color is allowed to organize.  It is not allowed to shout.

== What Quiet is

Quiet is a semantic interface color system designed for software used for
hours at a time.

It is built around a small vocabulary of visual roles rather than a collection
of application-specific color choices.

Quiet defines:

* ten canonical semantic anchors;
* Quiet Day and Quiet Night adaptations;
* deterministic derived colors;
* explicit readability constraints;
* contextual color rules;
* reference and compatibility exports;
* ports onto real software and operating environments.

Quiet is not a theme pack.

A port maps Quiet's semantics onto the native color vocabulary of its host.

Quiet ports color systems.

It does not skin applications.

== The system

Quiet Core defines ten canonical anchors.

[cols="1,1,1,1,1"]
|===
5+| Structure and reading

| Field
| Surface
| Structure
| Ink
| Muted

5+| Supporting structure and semantic signal

| Line
| Mineral
| Moss
| Ochre
| Rust
|===

The structural roles organize the interface.

The chromatic families carry limited semantic signal:

[cols="1,3"]
|===
| Family | Typical meaning

| Mineral
| information, focus, active state

| Moss
| success, nominal state, positive state

| Ochre
| warning, attention

| Rust
| error, destructive action, failure
|===

Color does not carry consequential meaning by itself.

Text, shape, position, iconography, typography, or another structural cue
must remain available when the distinction matters.

== Day and Night

Quiet Day and Quiet Night are adaptations of one semantic system.

They are not mathematical inversions.

Corresponding roles preserve semantic identity and recognizable color-family
character, but they are not required to preserve identical perceptual
lightness, chroma, hue, or prominence.

The canonical palette data is:

----
spec/quiet-day.json
spec/quiet-night.json
----

The specification is:

----
spec/quiet-core.adoc
----

== Use Quiet

The most direct Quiet-native outputs are currently:

[cols="1,2"]
|===
| Output | Location

| CSS / Web semantic variables
| `ports/web/quiet.css`

| Machine-readable semantic export
| `ports/machine/quiet.json`

| Generic ANSI terminal mapping
| `quiet port terminal`

| Terminal.app
| `ports/terminal/terminal-app/`
|===

Compatibility exports are also available for ecosystems that require them:

----
ports/base16/
ports/base24/
----

Base16 and Base24 are intentionally lossy compatibility projections.

They are not Quiet Core.

== Reference interface

A small reference interface exercises Quiet's structural and semantic roles
without introducing an application-specific theme vocabulary.

----
examples/reference-interface/
----

It consumes the generated Quiet CSS port directly.

The reference interface exists to test the system.

It is not intended to define what Quiet applications should look like.

== Engineering

Quiet treats color as a constrained system rather than a palette-selection
exercise.

The current reference implementation includes:

* sRGB as the canonical display space;
* OKLab and OKLCH for perceptual derivation;
* deterministic Selection and Callout derivations;
* contextual Subtle composition;
* WCAG 2.x contrast validation;
* nineteen current Core contrast requirements;
* sRGB gamut validation;
* color-vision-deficiency screening;
* external human review;
* controlled visual comparison when canonical values change.

The current canonical palettes pass the Core contract:

----
Quiet Day: PASS (19/19)
Quiet Night: PASS (19/19)
----

The canonical colors are intentionally conservative.

A passing color should not change merely because another value is
aesthetically interesting.

Changes should be supported by evidence.

== Reference implementation

Build:

----
make build
----

Validate the canonical palettes:

----
./bin/quiet check \
    spec/quiet-core.json \
    spec/quiet-day.json \
    spec/quiet-night.json
----

Inspect a color:

----
./bin/quiet inspect '#4A6E7A'
----

Calculate contrast:

----
./bin/quiet contrast '#1B1F1C' '#EEEADF'
----

Derive semantic display colors:

----
./bin/quiet derive spec/quiet-day.json
----

Generate an export:

----
./bin/quiet port web \
    spec/quiet-day.json \
    spec/quiet-night.json
----

All reference exports are reproducible from the canonical palette data.

== Source and evidence

The repository is organized around a separation between authored specification,
reference implementation, generated exports, and evidence.

----
spec/                 specification and canonical palette data
internal/color/       generic color mathematics
internal/core/        Quiet Core implementation
internal/port/        reference export implementations
ports/                generated and host-specific outputs
examples/             reference interfaces
reports/              analytical evidence
----

Project prose is written in AsciiDoc.

Analytical report sources are written in Org mode.

Markdown is intentionally not used.

== Status

Quiet Core 0.1 is under development.

The Day and Night palettes remain candidate data while broader reference-port
work and testing continue.

The existing reference exports are reproducible and covered by the repository
test suite.

== Contributing

See `CONTRIBUTING.adoc`.

When a host requires a role that Quiet does not define directly, prefer:

. an existing canonical anchor;
. an existing derived role;
. a documented contextual derivation;
. a port-specific extension as a last resort.

Port-specific extensions are not Quiet Core anchors.
